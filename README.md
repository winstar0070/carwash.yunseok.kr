# carwash.yunseok.kr — 세차 희석비율 계산기

**실행: [carwash.yunseok.kr](https://carwash.yunseok.kr)** · **[GitHub 저장소](https://github.com/winstar0070/carwash.yunseok.kr)**

물을 먼저 받아둔 뒤 세차 케미컬 원액을 얼마나 넣어야 하는지 계산하는 웹 앱입니다. 별도 설치 없이 운영 사이트에서 계산과 기기 내 저장을 사용할 수 있습니다.

**중간고사 과제: 바이브 코딩으로 앱 만들기 / 실습 미제출 → 신규 앱 제출.** README만으로 평가할 수 있도록 기획(PRD), 구현 Todo와 변경 근거, 사용한 스킬, 검증 범위와 회고를 이 문서에 함께 정리했습니다.

## 바로 사용하기

1. [carwash.yunseok.kr](https://carwash.yunseok.kr)에 접속합니다.
2. 물 용량을 **15L**, 원액:물 비율을 **1:500**으로 입력하면 필요한 원액은 **30ml**입니다.
3. 제품별 펌프 토출량을 알고 있다면 입력하여 정수 펌프 횟수와 별도 계량할 잔량을 확인합니다.
4. 자주 사용하는 설정은 ‘내 케미컬’에 저장해 다시 불러옵니다. 제품 검색을 이용할 때는 판매 옵션과 사용 방법을 선택하고 값을 확인합니다.
5. 기기 간 동기화가 필요하면 선택적으로 패스키 보관함을 연결합니다. 최초 온라인 로딩 이후 계산과 기기 내 저장은 오프라인에서도 사용하며, 서버 로그인·동기화와 최신 제품 조회에는 연결이 필요합니다.

농도 입력은 제품의 유효 성분 농도가 아니라 **완성액에서 원액이 차지하는 부피 비율**입니다. 농도 c%에서 `원액 ml = 물 ml × c / (100 - c)`로 계산합니다. 원액이 1,000ml 이상이면 L로 표시하되 내부 계산은 ml를 유지합니다.

## PRD — 무엇을, 왜 만드는가

**문제와 사용자:** 셀프 세차를 하는 사용자는 용기에 물을 받은 다음 제품 라벨의 비율을 원액 계량량으로 바꿔야 합니다. 제품·장비마다 비율이 다르고 현장에서 매번 계산하거나 입력하는 일이 번거롭습니다.

**목표:** 스마트폰에서 물 용량과 원액:물 비율을 입력하면 원액량을 즉시 보여주고, 자주 쓰는 제품 설정을 다시 불러올 수 있게 합니다. 인터넷 연결이 끊겨도 계산과 기기 내 저장을 유지합니다.

**핵심 흐름:** 물 용량 입력 → 비율 또는 농도 입력 → 원액량·펌프 횟수 확인 → 내 제품 저장 → 다음 세차 때 불러오기. 카탈로그를 이용하면 제품 검색 → 판매 옵션·사용 방법 선택 → 설정 확인 → 저장 순서로 진행합니다. 패스키 보관함은 선택적으로 연결합니다.

**요구사항과 완료 기준:**

- 물 기준 계산: 원액:물 `1:N`에서 `원액 ml = 물 ml / N`. 물 15L, 1:500이면 원액 30ml입니다.
- 농도 입력: 완성액에서 원액이 차지하는 부피 비율로 해석합니다. 물 1L, 농도 1%이면 원액 약 10.1ml입니다. 유효 성분 함량과 구분합니다.
- 계량 보조: 제품별로 확인한 펌프 토출량을 사용합니다. 원액 36ml, 5ml/회이면 7회 + 1ml 별도 계량입니다.
- 제품 저장: 이름·비율·물 용량·펌프 값을 저장하고 수정·삭제·불러오기를 제공합니다. 검색어를 제품명으로 저장하지 않습니다.
- 카탈로그: 판매 옵션과 사용 방법에 맞는 확인된 값만 자동 입력합니다. 미확인 비율이나 펌프 값을 추정하지 않으며 정량 캡슐을 액제 비율로 환산하지 않습니다.
- 패스키 동기화: 이메일·비밀번호 없이 보관함을 열고 변경을 자동 저장합니다. 오프라인 대기·충돌·계정 전환에서 다른 보관함으로 데이터가 섞이지 않도록 합니다.
- 설치·오프라인: 최초 온라인 로딩 후 계산기와 저장한 제품을 오프라인에서 사용합니다. 서버 로그인과 최신 카탈로그 조회에는 연결이 필요합니다.
- 디자인·배포: 흰 배경·검은 글자·한 열 구성의 기존 디자인을 유지합니다. 프런트엔드는 Cloudflare Pages 정적 빌드, 인증·동기화는 Node API와 PostgreSQL로 분리합니다.

자동 제품 추천이나 미확인 제조사 수치 추정은 요구 범위에 포함하지 않습니다. 구체적인 사용·실행 방법은 [사용 안내](docs/usage.md)와 [개발 안내](docs/development.md)에 정리했습니다.

## 느낀점과 결론

> 2026-10-27 제출용 정리. 구현과 변경 기록을 바탕으로 프로젝트에서 얻은 교훈을 정리했습니다.

초기 구현은 물의 양과 희석비율로 원액량을 계산하는 데 집중했다. 이후 제품 검색과 보관함을 추가하면서 제품마다 다른 사용 조건과 저장 흐름도 함께 다루게 됐다. 검색어와 저장할 제품명을 나누고, 확인되지 않은 수치를 자동 입력하지 않도록 한 변경은 데이터의 의미를 일관되게 유지하는 일이 중요함을 보여준다.

바이브 코딩으로 기능을 빠르게 늘릴 수 있었지만, 계산 입력 오류·오프라인·계정 전환처럼 정상 흐름 밖의 상황을 테스트로 확인하는 과정도 필요했다. Todo는 처음 정한 항목을 지우는 목록에 그치지 않고, 발견한 예외와 바뀐 결정을 기록하는 도구가 되어야 한다.

이 프로젝트는 단순 희석 계산기에서 제품 검색과 개인 보관함 동기화를 제공하는 앱으로 발전했다. 공개 저장소와 실행 주소를 통해 결과물을 확인할 수 있고, PRD·Todo 변경 내역과 테스트로 구현의 근거를 남겼다. 자동 테스트 통과와 실기기 검증은 구분해야 하며, 이후에는 미검증 흐름을 확인하고 작업별 검증·커밋·push 기록을 꾸준히 남기는 것이 다음 과제다.

## 개발자용 로컬 실행

Node.js 24 LTS와 pnpm 10.28.2(`package.json`의 `packageManager`)를 준비한 뒤 저장소 루트에서 실행합니다. 정적 파일 제공에는 Python 3을 사용합니다.

```bash
corepack enable
pnpm install --frozen-lockfile
npm run build
python3 -m http.server 8766 --directory dist
```

계산과 기기 내 저장은 [carwash.yunseok.kr](https://carwash.yunseok.kr)에서 바로 확인할 수 있습니다. 위 명령은 소스 수정 시 로컬 8766 포트에서 빌드 결과를 확인하기 위한 개발용 절차입니다. 패스키·동기화·최신 카탈로그에는 별도 API가 필요합니다. API 연결과 테스트는 [개발 안내](docs/development.md), 공개 배포는 [운영 안내](docs/deployment.md)를 따릅니다. 공개하는 디렉터리는 `dist/`입니다.

## 디렉터리

| 경로 | 역할 |
| --- | --- |
| `src/client/` | 계산기 HTML, 브라우저 모듈, 서비스 워커 소스 |
| `src/server/` | 패스키·보관함·카탈로그 API |
| `src/shared/` | 백업 데이터 형식 검증 모듈 (현재 API·테스트에서 사용) |
| `public/` | 허용 목록으로 배포하는 매니페스트·아이콘·헤더·404 |
| `db/migrations/` | PostgreSQL 스키마 변경 |
| `scripts/` | 정적 빌드·아이콘 생성·카탈로그 가져오기 |
| `tests/` | 단위·회귀·PostgreSQL 통합 테스트 |
| `docs/` | 제출·사용·개발·운영·디자인 문서 |
| `dist/` | 빌드 산출물 (Git 제외) |

루트의 `package.json`, `Dockerfile`, `compose.yaml`, `wrangler.json`은 실행·배포 진입점입니다. `.agents/`와 `.impeccable/`은 도구가 발견하는 기존 위치를 유지합니다. 소스 이동과 공개 URL의 관계는 [구조 결정 기록](docs/architecture.md)에 정리했습니다.
