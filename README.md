# carwash.yunseok.kr — 세차 희석비율 계산기

셀프 세차장에서 버킷·압축 분무기·폼랜스 등에 **물을 먼저 받아둔 뒤, 희석 비율(1:N)에 맞춰 투입해야 할 케미컬 원액 용량(ml)**을 즉시 계산해 주는 정적 웹 애플리케이션입니다.

## 중간고사 과제: 바이브 코딩으로 앱 만들기

**제출 유형: 실습 미제출 → 신규 앱 제출.** 이 프로젝트는 물을 먼저 받아둔 뒤 세차 케미컬을 얼마나 넣어야 하는지 계산하는 웹 앱입니다. 계산, 제품 보관, 제품 검색, 기기 간 동기화를 하나의 흐름으로 제공합니다.

- 실행 주소: <https://carwash.yunseok.kr>
- 코드: <https://github.com/winstar0070/carwash.yunseok.kr>
- 문서 기준: `15bafb2`까지의 구현 및 2026-10-21 제출 문서 정리. 실제 실습 제출본과의 비교는 해당하지 않습니다.
- **제출 전 확인:** 2026-10-21 조회 시 저장소는 **Private**입니다. 과제 제출을 위해 Public 전환이 필요합니다.

### PRD — 무엇을, 왜 만드는가

**문제와 사용자:** 셀프 세차를 하는 사용자는 용기에 물을 받은 다음 제품 라벨의 비율을 원액 계량량으로 바꿔야 합니다. 제품·장비마다 비율이 다르고 현장에서 매번 계산하거나 입력하는 일이 번거롭습니다.

**목표:** 스마트폰에서 물 용량과 원액:물 비율을 입력하면 원액량을 즉시 보여주고, 자주 쓰는 제품 설정을 다시 불러올 수 있게 합니다. 인터넷 연결이 끊겨도 계산과 기기 내 저장을 유지합니다.

**핵심 흐름:** 물 용량 입력 → 비율 또는 농도 입력 → 원액량·펌프 횟수 확인 → 내 제품 저장 → 다음 세차 때 불러오기. 카탈로그를 이용하면 제품 검색 → 판매 옵션·사용 방법 선택 → 설정 확인 → 저장 순서로 진행합니다. 패스키 보관함은 선택적으로 연결합니다.

**요구사항과 완료 기준:**

- 물 기준 계산: 원액:물 `1:N`에서 `원액 ml = 물 ml / N`. 물 15L, 1:500이면 원액 30ml입니다.
- 농도 입력: 완성액에서 원액이 차지하는 부피 비율로 해석합니다. 물 1L, 농도 1%이면 원액 약 10.1ml입니다. 유효 성분 함량과 구분합니다.
- 계량 보조: 제품별로 확인한 펌프 토출량을 사용합니다. 원액 36ml, 5ml/회이면 7회 + 1ml 별도 계량입니다.
- 제품 저장: 이름·비율·물 용량·펌프 값을 저장하고 수정·삭제·불러오기를 제공합니다. 검색어를 제품명으로 저장하지 않습니다.
- 카탈로그: 판매 옵션과 사용 방법에 맞는 확인된 값만 자동 입력합니다. 미확인 비율이나 펌프 값을 추정하지 않으며 정량 캡슐을 액제 비율로 환산하지 않습니다.
- 패스키 동기화: 이메일·비밀번호 없이 보관함을 열고 변경을 자동 저장합니다. 오프라인 대기·충돌·계정 전환에서 다른 보관함으로 데이터가 섞이지 않도록 합니다.
- 설치·오프라인: 최초 온라인 로딩 후 계산기와 저장한 제품을 오프라인에서 사용합니다. 서버 로그인과 최신 카탈로그 조회에는 연결이 필요합니다.
- 디자인·배포: 흰 배경·검은 글자·한 열 구성의 기존 디자인을 유지합니다. 프런트엔드는 Cloudflare Pages 정적 빌드, 인증·동기화는 Node API와 PostgreSQL로 분리합니다.

자동 제품 추천이나 미확인 제조사 수치 추정은 요구 범위에 포함하지 않습니다. 구체적인 사용·실행 방법은 아래 기능 설명에 정리했습니다.

# 세차 계산기 제출 검토

- 먼저 AGENT.md와 README.md를 읽고, 화면 변경이 있으면 DESIGN.md도 확인한다.
- 최초 계획 원본이 없으면 초기 커밋에서 확인되는 기능을 재구성한 것이라고 밝힌다. 커밋 날짜를 push 날짜나 실제 실습 제출일로 표현하지 않는다.
- 물을 먼저 받는 기준을 유지한다. 원액:물 = 1:N이면 원액 ml = 물 ml / N이다. 완성액 원액 농도 c%이면 원액 ml = 물 ml × c / (100 - c)이다.
- 펌프 토출량은 근거가 있는 값만 사용한다. 정수 펌프 횟수와 남은 별도 계량량을 안내하고, 임의의 반 펌프나 반올림을 가정하지 않는다.
- 제품 검색어와 저장 제품명을 구분하고, 판매 옵션·사용 방법 미선택과 정량 캡슐의 비례 환산 제한을 확인한다.
- Todo 변경은 초기 상태, 최종 결정, 이유, 관련 커밋 또는 테스트 파일을 연결해 설명한다. 기록에 없는 테스트 수행이나 당시의 동기를 꾸며 쓰지 않는다.
- npm test와 npm run build를 실행해 결과를 기록한다. PostgreSQL 통합 테스트, 실기기 패스키, 운영 배포 검증은 실제 수행한 경우에만 통과로 적는다.
- 스킬의 이번 사용과 과거 사용을 구분한다. 개인 회고는 작성자 확인 전 초안으로 표시한다.

처음에는 물의 양과 희석비율로 원액량을 계산하면 충분하다고 생각했지만, 앱을 발전시키면서 제품마다 다른 사용 조건과 저장 흐름을 함께 다뤄야 한다는 점을 배웠다. 특히 검색어와 저장할 제품명을 나누고, 확인되지 않은 수치를 자동 입력하지 않도록 만든 과정에서 기능의 수보다 데이터의 의미를 일관되게 유지하는 일이 중요하다고 느꼈다.

바이브 코딩으로 기능을 빠르게 늘릴 수 있었지만, 계산 입력 오류·오프라인·계정 전환처럼 정상 흐름 밖의 상황을 테스트로 확인하는 과정도 필요했다. Todo는 처음 정한 항목을 지우는 목록에 그치지 않고, 발견한 예외와 바뀐 결정을 기록하는 도구가 되어야 한다.

이 프로젝트는 단순 희석 계산기에서 제품 검색과 개인 보관함 동기화를 제공하는 앱으로 발전했다. 남은 제출 작업은 개인 회고를 확정하고 저장소를 공개하며, 이후 변경을 검증·커밋·push하는 과정을 꾸준히 남기는 것이다.

## 주요 기능

- **물 용량 고정 기준 원액 산출 (`원액 ml = 물 ml ÷ N`)**:
  - 리터(`L`) / 밀리리터(`ml`) 단위 전환 및 직관적인 `−` / `+` 스테퍼 조절
  - 셀프 세차장 필수 용기 퀵 프리셋 (1L 폼랜스, 1.5L/2L 압축분무기, 4L 미니버킷, 10L/12L/15L/18L 버킷)
- **희석 비율(`1:N`) 실시간 계산**:
  - 희석비율 대신 완성액의 원액 농도(부피 %)를 직접 입력 가능
  - 물을 먼저 받는 기준: `원액 ml = 물 ml × 농도 / (100 - 농도)`. 예: 물 1L, 농도 1% → 원액 약 10.1ml
  - 1:5 (휠/타이어), 1:10 (APC/폼랜스), 1:20~30 (프리워시), 1:300~1000 (카샴푸) 퀵 칩 및 직접 입력
- **실시간 계량컵 눈금 가이드 & 환산**:
  - 30ml / 50ml / 100ml / 250ml 계량컵 기준 눈금 채움 시각화
  - 소분 캡 횟수, 제품별 펌프 횟수, 혼합 후 총 용량 동시 안내
  - 희석비율의 `+`·`−`는 10씩 조정합니다. 원액이 1,000ml 이상이면 결과·저장 목록·복사 내용을 L로 표시하고, 펌프 계산은 원래 ml 값으로 수행합니다.
- **내 케미컬 보관함 (`localStorage`)**:
  - 자주 사용하는 카샴푸·프리워시·APC 등의 이름, 분류, 권장 희석비율, 기본 물 용량, 메모를 브라우저에 저장하고 터치 한 번으로 불러오기

## 제품별 펌프

- 계산 결과 아래에 펌프 1회 토출량(ml)을 입력하면 횟수를 계산합니다. 프리셋에도 제품별 토출량을 저장할 수 있습니다.
- 정수 횟수로 부족한 원액은 별도 계량량으로 표시합니다. 예: 원액 36ml, 펌프 5ml/회 → 7회 + 1ml 별도 계량. 반 펌프나 임의 반올림을 가정하지 않습니다.
- 기본 데이터는 이 브라우저에 저장됩니다. 패스키 보관함을 열면 서버에 동기화할 수 있습니다. 브라우저 데이터 삭제 전에 대기 중인 변경사항을 동기화하세요.

## 패스키 보관함과 동기화

- 이름·이메일·비밀번호 없이 패스키를 등록합니다. 서버는 무작위 보관함 ID, 패스키 공개키, 제품 목록을 PostgreSQL에 저장합니다.
- 새 보관함을 만들면 현재 기기의 목록을 자동 저장합니다. 기존 보관함을 열면 서버 목록을 불러오고, 이후 제품 추가·수정·삭제를 바로 자동 저장합니다. 마지막 제품을 삭제한 빈 목록도 그대로 동기화합니다.
- 저장 중 생긴 변경도 순서대로 전송하며, 목록 아래에 서버 저장 중·저장 완료·오프라인 대기 상태를 표시합니다. 다른 기기에서 같은 목록을 변경해 충돌한 경우에만 사용할 목록을 선택합니다. ‘합치기’는 삭제한 항목을 다시 추가할 수 있습니다.
- 화면을 보고 있을 때 15초마다, 다시 화면으로 돌아올 때와 재연결 시 서버 변경을 확인합니다. 달라진 목록만 반영하고 새로 불러온 상태를 표시합니다. 제품을 작성 중이면 저장·취소 후 반영하며, 기기의 미전송 변경을 새 서버 목록으로 덮어쓰지 않습니다.
- 오프라인 변경사항은 보관함별로 기기에 대기시킵니다. 재연결·재접속 시 자동으로 전송하고 일시적 오류는 재시도하며, 충돌 시 자동으로 덮어쓰지 않습니다. 기존 비회원 목록은 별도로 보관하고 로그아웃하면 복원합니다.
- 여러 탭에서 보관함을 바꿔도 다른 보관함에 저장되지 않도록 조회·저장·계정 관리 요청의 대상 ID를 세션과 대조합니다. 대상이 바뀌면 연결을 중단하고 미전송 변경은 원래 보관함의 기기 대기 목록에 유지합니다.
- 보관함을 만들 때 복구 코드가 표시됩니다. 별도 파일로 보관하세요. 서버에는 코드의 해시만 저장합니다. 복구 시 기존 세션·패스키를 해제하고 새 코드를 발급하므로 패스키를 다시 추가해야 합니다.
- 패스키를 분실하고 복구 코드도 없으면 보관함을 복구할 수 없습니다. 패스키 자체는 제품 데이터를 백업하거나 동기화하지 않습니다.

## 오프라인 및 설치

- 처음 온라인으로 접속하면 계산기 파일이 기기에 저장됩니다. 하단 ‘홈 화면에 추가 · 오프라인 사용’을 펼쳐 준비 완료를 확인하세요.
- Android: 브라우저의 ‘앱 설치’ 또는 ‘홈 화면에 추가’. 설치를 지원하는 브라우저에서는 페이지 안에도 설치 버튼이 나타납니다.
- iPhone·iPad: Safari 공유 메뉴 → ‘홈 화면에 추가’.
- 이후에는 오프라인에서도 사이트를 다시 열어 계산하고 저장한 비율을 사용할 수 있습니다. 글꼴이 저장되지 않았으면 시스템 글꼴로 표시됩니다.
- HTTPS 또는 localhost에서 동작합니다. 브라우저 데이터 삭제 시 저장한 비율과 오프라인 파일도 삭제될 수 있습니다.
- 파일을 수정해 배포할 때는 `sw.js`의 `CACHE_NAME` 버전도 올려 주세요. 다음 온라인 접속에서 페이지가 갱신되고 새 서비스 워커가 캐시를 교체합니다.
- 빌드는 실행 스크립트와 API 설정을 내용 해시가 붙은 `/assets/...js`로 연결하고 오프라인 캐시 목록도 함께 갱신합니다. 해시 파일에는 1년 `immutable` 캐시를 적용하고, HTML·서비스 워커·기존 호환 URL은 재검증합니다. 이전 서비스 워커의 설정·스크립트가 새 화면에 섞이지 않게 합니다.
- 오프라인 HTML은 `/`에 한 번만 저장하며 `/index.html`도 같은 캐시로 복구합니다. 빌드에서는 번들에 포함된 카탈로그 모듈을 별도로 사전 캐시하지 않습니다. 네트워크 응답을 받은 뒤 캐시 저장은 백그라운드로 처리하므로 저장소 쓰기를 기다리지 않고 화면을 표시합니다.
- 아이콘 재생성: `python3 scripts/generate-icons.py` (외부 패키지 불필요).

## Cloudflare Pages 배포 설정

프런트엔드는 정적 파일로 배포합니다. 빌드는 패스키 브라우저 라이브러리를 묶으며 서버 코드는 출력 폴더에 포함하지 않습니다.

- **프레임워크 프리셋 (Framework preset)**: `None`
- **빌드 명령어 (Build command)**: `npm run build`
- **빌드 출력 디렉터리 (Build output directory)**: `dist`
- **환경 변수**: `CARWASH_API_BASE=https://carwash-api.yunseok.kr/api` (기본값과 같으며, 기존에 다른 값을 설정했다면 갱신)
- API는 프런트엔드와 같은 사이트의 HTTPS 도메인으로 연결합니다. 예: `carwash.yunseok.kr` + `carwash-api.yunseok.kr`. 서로 다른 사이트에서는 세션 쿠키가 전달되지 않습니다.
- 현재 화면에 ‘배포 명령’이 필수라면 Workers 설정입니다. Pages의 Git 연동 프로젝트를 생성하고 위 빌드·출력 폴더를 지정하세요.

`wrangler.json`에도 Pages 프로젝트 `carwash-yunseok-kr`의 출력 폴더를 `./dist`로 지정합니다. 기존 프로젝트는 대시보드의 빌드 명령이 `npm run build`인지 확인한 뒤 재배포하세요. 저장소 루트(`.`)를 업로드하거나 루트에서 정적 서버를 실행하면 `.env.example`, Compose 설정, 서버 소스가 공개될 수 있습니다.

빌드는 이전 `dist`를 지운 뒤 계산기 실행에 필요한 HTML·번들·스크립트·PNG만 복사합니다. `.env*`, `server/`, `migrations/`, `scripts/`, 저장소 문서는 공개 산출물에 포함하지 않습니다. 최상위 `404.html`로 없는 경로의 계산기 HTML 대체 응답을 막습니다. 배포 후 `/`와 `/config.js`는 정상 응답하고 `/.env.example`, `/.env`, `/compose.yaml`, `/server/app.js`는 **404**인지 확인하세요.

## 별도 Docker 서버 실행

Docker Compose로 Node API와 PostgreSQL 17을 함께 실행합니다. SQLite는 사용하지 않습니다. 데이터베이스 포트는 외부에 노출하지 않으며 API는 호스트의 `127.0.0.1:8787`에 연결됩니다.

`.env.example`을 `.env`로 복사한 뒤 `POSTGRES_PASSWORD`에 직접 생성한 긴 임의 값을 넣으세요. 연결 URL에 안전하게 넣으려면 `openssl rand -hex 32`로 생성한 값을 사용하세요. `.env`는 커밋하지 않습니다.

```dotenv
POSTGRES_PASSWORD=직접_생성한_임의의_16진수_값
ORIGIN=https://carwash.yunseok.kr
RP_ID=carwash.yunseok.kr
```

```bash
docker compose up -d --build
docker compose ps
curl http://127.0.0.1:8787/api/health
```

리버스 프록시에서 `https://carwash-api.yunseok.kr`를 `http://127.0.0.1:8787`로 연결하고 `/api/...` 경로를 그대로 전달하세요. `ORIGIN`은 프런트엔드 주소(끝 슬래시 없음), `RP_ID`는 그 호스트명입니다. 이미 등록한 패스키를 유지하려면 RP_ID를 바꾸지 마세요. 프록시가 다른 컨테이너라면 같은 Docker 네트워크의 `api:8787`로 연결합니다.

보관함 대상 검증 업데이트는 API를 먼저 재배포한 뒤 프런트엔드를 배포하세요. 구형 클라이언트의 대상 ID 없는 요청은 `428`로 거부하므로 열린 페이지를 새로고침해야 합니다. 신형 클라이언트가 구형 API에 연결하면 동기화를 멈추고 서버 업데이트를 안내하며 기기의 변경사항을 보존합니다. 제품 조회는 `GET /api/presets?vaultId=<보관함 ID>`, 저장·로그아웃·복구 코드 재발급은 JSON의 `vaultId`를 필수로 받습니다. 패스키 등록의 options/verify에도 추가할 보관함 ID를 보내며 신규 생성은 명시적으로 `vaultId: null`을 보냅니다.

데이터는 `carwash-data` 볼륨에 영구 저장되며 시작 시 스키마를 적용합니다. 운영 시 별도로 DB 백업을 보관하세요. 다음 명령은 실행한 폴더에 백업 파일을 만듭니다.

```bash
docker compose exec -T db pg_dump -U carwash carwash > carwash-backup.sql
```

요청 제한은 직접 연결 주소 기준입니다. 리버스 프록시 뒤에서는 방문자가 제한을 공유하므로 공개 운영 규모에 맞춰 프록시에서도 요청 제한을 설정하세요.

- 패스키 등록 요청은 IP당 시간당 10회, 서버 전체 시간당 100회까지 허용합니다. 취소한 등록도 요청 횟수에 포함합니다.
- 새 보관함 생성은 IP당 하루 5개, 서버 전체 하루 100개까지 허용합니다. 검증과 저장이 성공한 경우만 생성 횟수에 포함합니다. 기존 보관함에 패스키를 추가할 때는 이 생성 한도를 사용하지 않습니다.
- 시간·일 한도는 UTC 정시·자정에 갱신되며 PostgreSQL에 저장되어 서버 재시작과 여러 API 인스턴스에서도 공유됩니다. 초과 시 `429`와 남은 대기 시간(초)의 `Retry-After` 헤더를 반환합니다. 로그인에는 별도의 기존 요청 제한이 적용됩니다.
- 보관함당 패스키는 최대 10개이며, 동시 등록 시에도 저장 직전에 보관함을 잠그고 한도를 다시 확인합니다.

## 공용 제품 카탈로그

제품 조사 JSON(`schema_version: "1.0.0"`)은 개인 패스키 보관함과 별도인 공용 카탈로그에 저장합니다. API를 실행한 뒤 원본 파일을 표준 입력으로 전달하세요. 원본 파일은 컨테이너 이미지에 포함하지 않습니다.

```bash
docker compose exec -T api node scripts/import-products.mjs - < /path/to/carwash_products.json
curl http://127.0.0.1:8787/api/products
curl http://127.0.0.1:8787/api/products/db-05442
```

- `GET /api/products`: 출처·조사일·비율 기준과 전체 제품 목록을 반환합니다. `?view=picker`를 붙이면 검색 화면에서 사용하지 않는 `research_log`만 제외하며, 제품별 사용 지침·프로필·출처는 유지합니다.
- `GET /api/products/:product_id`: 해당 제품의 옵션·pH 근거·희석·펌프 프로필을 반환합니다. 두 API 모두 로그인 없이 조회하며 HTTP로 수정할 수 없습니다.
- 가져오기는 한 트랜잭션 안에서 제품 목록을 한 번의 배치 upsert로 처리합니다. 같은 `product_id`는 갱신하므로 재실행해도 중복되지 않으며, 파일에 없는 기존 제품과 개인 보관함은 삭제하지 않습니다. 제품이나 메타데이터 저장이 실패하면 배치 전체를 롤백합니다. 최상위 조사 메타데이터는 마지막 가져오기 기준입니다.
- `null`, `unknown`, `calculation_allowed: false`, 단측 희석 상한, 펌프 호환 조건과 출처는 그대로 보존합니다. 소비자는 계산이 허용된 프로필의 명시된 값만 사용해야 하며, 미확인 값을 추정하거나 범위를 임의 보간하지 마세요.
- ‘프리셋 추가’의 **제품 검색**에 브랜드·제품명·판매 옵션을 입력하면 DB의 공용 카탈로그를 검색합니다. 결과를 클릭하거나 Enter로 선택하면 별도의 **케미컬 이름**에 실제 제품명이 채워집니다. 판매 옵션과 사용 방법을 확인한 뒤 저장하세요. 검색어만 입력한 상태로는 저장되지 않습니다.
- 선택한 제품명은 읽기 전용이며 ‘직접 입력으로 전환’으로 수정할 수 있습니다. 카탈로그에 없는 제품은 ‘직접 입력’을 선택하거나 케미컬 이름을 직접 작성합니다. 다시 검색하면 이전 제품의 이름·설정·출처를 지워 서로 다른 제품 정보가 섞이지 않게 합니다.
- `calculation_allowed: true`이며 원액:물 기준이 확인된 해당 판매 옵션의 비율만 자동 입력합니다. 범위나 한쪽 한계값만 등록된 경우에는 원문 조건을 확인하고 값을 선택하거나 직접 입력해야 합니다. 다른 용량의 희석비율이나 펌프 정보는 상속하지 않습니다.
- 물 용량은 제조사 권장량이 아닌 수정 가능한 **앱의 장비 기본값**입니다(버킷 15L, 폼랜스 1L, 압축분무기 1.5L). 기본값이 없는 방법은 물 용량을 직접 입력합니다. 폼랜스 비율은 통 사전 혼합비이며 분사 후 농도와 다릅니다.
- DB에 구조화된 권장 물량이 확인되어 있으면 앱 기본값보다 우선하며 근사 여부를 표시합니다. 정량 캡슐처럼 `proportional_scaling_allowed: false`인 지침은 권장 물량과 원문만 안내하고 비율 프리셋 저장을 막습니다. 캡슐을 쪼개거나 물 양에 비례하는 액제 비율로 환산하지 않습니다.
- 펌프는 정량 근거가 있는 호환 모델을 사용자가 선택한 경우에만 채웁니다. 별도 판매 펌프를 기본 제공으로 가정하지 않으며 확인되지 않은 토출량은 비워 둡니다.
- 공개 카탈로그 조회에는 인증 쿠키를 보내지 않습니다. 마지막으로 조회한 공용 목록을 브라우저에 보관해 다음 검색에서 즉시 표시하고 백그라운드로 갱신하며, 개인 패스키 보관함 데이터와 분리합니다. 갱신된 목록은 다음 검색부터 적용하고 이미 표시한 후보나 선택 중인 제품의 값은 바꾸지 않습니다. API 연결 실패 때도 저장된 목록을 계속 사용하며, 저장된 목록도 없으면 직접 입력을 계속할 수 있습니다. 조사일과 원문 출처를 확인하고 실제 제품의 최신 지침을 따르세요.

## 로컬 개발 및 검증

```bash
corepack enable
pnpm install --frozen-lockfile
# .env의 ORIGIN=http://localhost:8766, RP_ID=localhost로 설정
docker compose up -d --build
CARWASH_API_BASE=http://localhost:8787/api pnpm build
python3 -m http.server 8766 --directory dist
```

별도 터미널에서 실행합니다. 통합 테스트는 테스트 전용 PostgreSQL 연결을 요구하며 임시로 생성한 보관함을 정리합니다.

```bash
pnpm test
TEST_DATABASE_URL=postgres://사용자:비밀번호@테스트DB호스트:5432/테스트DB pnpm test:api
```

통합 테스트는 실제 공개키 검증을 수행하는 소프트웨어 인증기를 사용합니다. 기기별 지문·Face ID·보안 키의 실제 등록 및 설치 동작은 지원 브라우저에서 확인해야 합니다.
