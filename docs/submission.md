### PRD — 무엇을, 왜 만드는가

**문제와 사용자:** 셀프 세차를 하는 사용자는 용기에 물을 받은 다음 제품 라벨의 비율을 원액 계량량으로 바꿔야 합니다. 제품·장비마다 비율이 다르고 현장에서 매번 계산하거나 입력하는 일이 번거롭습니다.

**목표:** 스마트폰에서 물 용량과 원액:물 비율을 입력하면 원액량을 즉시 보여주고, 자주 쓰는 제품 설정을 다시 불러올 수 있게 합니다. 인터넷 연결이 끊겨도 계산과 기기 내 저장을 유지합니다.

**핵심 흐름:** 물 용량 입력 → 비율 또는 농도 입력 → 원액량·펌프 횟수 확인 → 내 제품 저장 → 다음 세차 때 불러오기. 카탈로그를 이용하면 제품 검색 → 판매 옵션·사용 방법 선택 → 설정 확인 → 저장 순서로 진행합니다. 패스키 보관함은 선택적으로 연결합니다.

**요구사항과 완료 기준:**

- 물 기준 계산: 원액:물 `1:N`에서 `원액 ml = 물 ml / N`. 물 15L, 1:500이면 원액 30ml입니다.
- 농도 입력: 완성액에서 원액이 차지하는 부피 비율로 해석합니다. 물 1L, 농도 1%이면 원액 약 10.1ml입니다. 유효 성분 함량과 구분합니다.
- 계량 보조: 제품별로 확인한 펌프 토출량을 사용합니다. 원액 36ml, 5ml/회이면 7회 + 1ml 별도 계량입니다.
- 제품 저장: 이름·비율·물 용량·펌프 값을 저장하고 수정·삭제·불러오기를 제공합니다. 검색어를 제품명으로 저장하지 않습니다.
- 카탈로그: 판매 옵션과 사용 방법에 맞는 확인된 값만 자동 입력합니다. 미확인 비율이나 펌프 값을 추정하지 않으며 정량 캡슐을 액제 비율로 환산하지 않습니다.
- 패스키 동기화: 이메일·비밀번호 없이 보관함을 열고 변경을 자동 저장합니다. 오프라인 대기·충돌·계정 전환에서 다른 보관함으로 데이터가 섞이지 않도록 합니다.
- 설치·오프라인: 최초 온라인 로딩 후 계산기와 저장한 제품을 오프라인에서 사용합니다. 서버 로그인과 최신 카탈로그 조회에는 연결이 필요합니다.
- 디자인·배포: 흰 배경·검은 글자·한 열 구성의 기존 디자인을 유지합니다. 프런트엔드는 Cloudflare Pages 정적 빌드, 인증·동기화는 Node API와 PostgreSQL로 분리합니다.

자동 제품 추천이나 미확인 제조사 수치 추정은 요구 범위에 포함하지 않습니다. 구체적인 사용·실행 방법은 [사용 안내](usage.md)와 [개발 안내](development.md)에 정리했습니다.

### 느낀점과 결론

> 2026-10-27 제출용 정리. 구현과 변경 기록을 바탕으로 프로젝트에서 얻은 교훈을 정리했습니다.

초기 구현은 물의 양과 희석비율로 원액량을 계산하는 데 집중했다. 이후 제품 검색과 보관함을 추가하면서 제품마다 다른 사용 조건과 저장 흐름도 함께 다루게 됐다. 검색어와 저장할 제품명을 나누고, 확인되지 않은 수치를 자동 입력하지 않도록 한 변경은 데이터의 의미를 일관되게 유지하는 일이 중요함을 보여준다.

바이브 코딩으로 기능을 빠르게 늘릴 수 있었지만, 계산 입력 오류·오프라인·계정 전환처럼 정상 흐름 밖의 상황을 테스트로 확인하는 과정도 필요했다. Todo는 처음 정한 항목을 지우는 목록에 그치지 않고, 발견한 예외와 바뀐 결정을 기록하는 도구가 되어야 한다.

이 프로젝트는 단순 희석 계산기에서 제품 검색과 개인 보관함 동기화를 제공하는 앱으로 발전했다. 공개 저장소와 실행 주소를 통해 결과물을 확인할 수 있고, PRD·Todo 변경 내역과 테스트로 구현의 근거를 남겼다. 자동 테스트 통과와 실기기 검증은 구분해야 하며, 이후에는 미검증 흐름을 확인하고 작업별 검증·커밋·push 기록을 꾸준히 남기는 것이 다음 과제다.
